## 6. Known gaps and risks (honest list)

1. **Live Telegram unverified** (G6 BLOCKED). Bot API field names follow the official docs; re-check the
   changelog and run `telegram_setup_webhook.py` + a real Business account before any pilot.
2. Outbound (contractor) messages are stored but **not** given to the AI as context (the existing prompt has
   no context slot; mixing them in would create false requirements).
3. Derived commercial records (request text, items, finding summaries, CO snapshots) are not erased by
   retention or "Delete stored messages" — needs a product/legal decision.
4. No manual split/merge UI for signals; dedup is conservative (Jaccard ≥ 0.5 within a category family).
5. AI rationale language does not follow the UI locale.
6. Bad-secret throttle is per process; no secret manager, TLS, global rate limit or IP allowlist (infrastructure).
7. No CI workflow; no automated browser E2E; no 5× consecutive E2E run; evaluation metrics (precision/recall)
   not measured — targets only.
8. Kazakh locale not added (spec: separate stage).
9. Compatibility: local JWT issuer/audience and browser storage keys were renamed → users sign in once again
   and theme/language preferences reset once. Existing DB names in deployed envs are untouched (configure via
   `DATABASE_URL`).
10. v1 Commercial Authorization (`Start Work` gate, receipts, client acceptance, baseline v2) remains backlog
    (spec §19); the UI does not claim it.
